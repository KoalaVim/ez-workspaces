## Why

`ez session enter <name>` fails for sessions that have env vars (e.g. PR metadata) because the shell wrapper's re-invocation loop treats env export statements in `post_cmd_file` as a "re-launch" signal, triggering a second `ez` invocation with `--repo <worktree-path>` which is not a valid repo identifier.

## What Changes

- Fix the shell wrapper loop to distinguish between "re-invoke the browser" post-commands and "export env vars" post-commands, so that env-only post-commands don't trigger a spurious re-invocation
- The fix must apply to all shell variants: bash/zsh, fish, and pwsh

## Capabilities

### New Capabilities

(none)

### Modified Capabilities

- `session-management`: The enter-session flow must not fail when a session carries env vars (e.g. PR metadata). Env exports written to `post_cmd_file` must not trigger the shell wrapper's re-invocation loop.

## Impact

- `src/main.rs` — shell wrapper functions generated by `print_shell_init` (bash/zsh, fish, pwsh variants)
- Alternatively, `src/browser/mod.rs` or `src/session/mod.rs` — the Rust code that decides what to write to `post_cmd_file` could be changed to use a separate signaling mechanism
- Sessions with env vars (PR metadata from `detect_pr_for_session`) are the most common trigger
